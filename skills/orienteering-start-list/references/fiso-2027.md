# Italy: FISO Start List Guidelines From 2027

Use this reference for Italian events (FISO — Federazione Italiana Sport Orientamento) held in 2027 or later, or whenever the organizer asks for the "nuove indicazioni FISO". These rules apply to Italy only; do not apply them to WRE/IOF or foreign events unless the organizer asks.

## What Changes

1. **Unchanged limits.** The total start window must stay contained, and the start load stays at 4-6 starters per minute, never more than 8 — **per physical start**. Events with separate starts (start 1, start 2, ...) have that throughput on each of them.
   - 5 or 6 per minute per start is fine for every race type (automatic window: about 5.5 on average). With 3 or more separate starts aim at 4-5 per start; 6 with short peaks up to 8 is still fine when a maximum window must be respected.
   - The organizer can raise the limit up to 8 (`max_load: 8`) to shorten a long grid (e.g. a large sprint).
   - Each start ramps up gradually: 1 starter in the first minute, 2 in the second, 4 in the third, then normal pace, so the start crew can settle in.
2. **Different courses for all categories.** FISO asks course setters to give every category its own course. Courses arrive already made, so this only means there are more distinct courses and first controls to check. Keep checking first-control collisions per minute as usual.
3. **Larger intervals within the same category:**
   - Master categories (35+: M35, W35, M40 ... W75 and above): **minimum 2 minutes in sprint, 3 minutes in all other races** (middle, long, etc.).
   - In all non-sprint races, **every category** (not only masters) should get a wider interval when entries and window allow it: 4, 5, 6 or even 7 minutes are fine. Smaller categories naturally get the widest gaps.
   - The interval must stay **constant within each category**; it can differ between categories.
   - Widening never justifies a longer total window: spread each category over the existing window instead.
   - Sprint keeps the usual short intervals (1 minute, masters 2) unless the organizer asks for more.
4. **Randomization by strength groups** using a ranking (Coppa Italia, lista base/ranking list, or another list the organizer names):
   - Default: split the ranked category in **about three strength groups** (weakest/unranked first, strongest last) and shuffle within each group.
   - **Elite categories:** three groups are too coarse (the strongest athlete must not start 51st out of 75). Shuffle in **blocks of 5 or 10** from the end of the category instead, so the strongest runners stay in the final block.
   - Unranked athletes count as weakest and fall in the first group.
   - Report the seed and use a different seed per stage in multi-day events.
5. **No same-club athletes one after the other** in the same category, except in very small categories (fewer than 4 athletes) or when one club has so many entries that it is impossible. In seeded categories this is first attempted inside each strength group/block; if that is not enough, an athlete may be moved to the **adjacent** group/block (never further). The organizer prefers this small seeding change to two same-club athletes in a row.
6. **Vacants:** 2 per grid category, but only 1 in small categories (fewer than 10 athletes) — always at least one.

## Applying It With The Script

Set `"ruleset": "fiso-2027"` in the config. The script then:

- Detects master categories from the name (`M35`, `W 40`, `D45`, `H-50`, ...; age ≥ `master_min_age`, default 35). Override per category with `"master": true/false` for non-standard names.
- Raises master intervals to at least `master_min_interval_sprint` (default 2) in sprint and `master_min_interval` (default 3) otherwise, even if a lower `interval` is configured. The report says when an interval was raised.
- Chooses the intervals itself, inside a contained window:
  1. The window is `window_minutes` if given; otherwise it is computed: long enough for the longest category at its minimum interval, for the busiest first control (one starter per minute per first control) and for an average of `target_load` starters per minute per start (default `max_load` − 0.5, i.e. 5.5; `max_load` − 1.5 with 3 or more starts). Several category orders are tried (`placement_attempts`, default 30); if none fits, the automatic window grows in 3% steps.
  2. **Too few first controls:** a grid without first-control collisions is searched up to an acceptable length (`max_window_stretch`, default +25% over what entries and load need; up to 15% beyond the busiest first control when that is still realistic, i.e. within `first_control_realistic` = +50%). Beyond that, and for a fixed `window_minutes` that cannot be met, the script accepts the fewest first-control collisions it can find and prints a WARNING with the length a collision-free grid would need. Example: Begun Cup 2025 middle (8 first controls for 486 athletes): 128 minutes with 70 collisions instead of an unrealistic 400+ minutes; the real grid had 139 collisions in 143 minutes.
  3. Every category starts at its minimum interval. Then, one minute at a time, the category with the smallest interval is widened (ties: the larger category first) and all categories are placed again; the change is kept only if everything still fits the window, no minute goes over `max_load` and no first-control collision appears. This spreads the available room fairly instead of giving it to whichever category is placed first.
  4. The upper limit is `fiso_max_interval` (default 7) in non-sprint races, or `max_interval` / `master_max_interval` / per-category `max_interval` when set. In sprint, widening only happens when a maximum is set explicitly.
- Separates same-club neighbours in every category with a random component (fully random, strength groups or elite blocks): first by swapping inside each group/block, then, only for the cases left, by moving athletes to the adjacent group/block (`club_move_to_neighbour_group`, default true; the report counts moved athletes). Categories with fewer than `club_separation_min_entries` (default 4) athletes are left alone. Same-club separation has priority over varying neighbours between races.
- For ranked categories (those with `rank_mode`, `invert_ranking`, `random_block` or `random_groups` in their config): uses `random_block` or `random_groups` if given; otherwise categories whose name contains "Elite" get blocks of `elite_random_block` (default 5), and all other ranked categories get `default_random_groups` (default 3) strength groups.
- Caps `peak_load` at 8 and keeps `max_load` at 6 unless configured otherwise (at most 8).

Example:

```json
{
  "ruleset": "fiso-2027",
  "race_type": "middle",
  "first_start": "10:00:00",
  "max_load": 6,
  "random_seed": 20270412,
  "stage": 1,
  "categories": {
    "M Elite": {"rank_mode": "points", "invert_ranking": true, "random_block": 5},
    "W Elite": {"rank_mode": "points", "invert_ranking": true, "random_block": 5},
    "M20": {"rank_mode": "points", "invert_ranking": true},
    "W20": {"rank_mode": "points", "invert_ranking": true}
  }
}
```

## Weekends And Multi-Day Events: Vary The Neighbours

When there are two races in a weekend or a multi-day event, the start lists should not pair the same runners again: two athletes who started one after the other in a previous race should not be consecutive again in the same category. This gives variety (different people to meet or follow in the forest).

With the script, build the races in order and pass the earlier proposals with `previous_start_lists` (e.g. `["day1.csv"]` for day 2, `["day1.csv", "day2.csv"]` for day 3). Use stable `id` values across races. The script swaps athletes only inside their shuffle scope (whole category for random categories, the same strength group or elite block for seeded ones), so the seeding is preserved, and keeps club separation as far as possible. Categories in fixed ranking order are not changed. Very small categories (e.g. 3 athletes) may make a repeat unavoidable: the report gives the number of repeated pairs per category.

## Shared First Controls: Use Compatible Intervals

Categories sharing a first control must use compatible intervals. A category at 2 minutes takes every other minute; one at 3 minutes alternates between even and odd minutes and hits it every second start, so while the 2-minute category is starting the 3-minute ones cannot start at all on that control. With FISO 2027 this happens often (masters at 3 minutes on the same first control as an elite or youth class at 2). When the grid does not fit, the script first gives every category on a shared first control the largest interval of its group (where it still fits the window), and only then lengthens the window. Tested on 2026 races: Eridano middle 174 → 137 minutes (real 2026: 134), Coppa Italia final middle 161 → 137 (real 142), Venezia by night 141 → 115 (real 112).

## Shared First Controls Lengthen The Grid

Tested on 2026 national events (LiveResults data): when several courses share the same first control, as was common in 2026, the master minimum of 3 minutes plus "no two starters on the same first control in the same minute" can make the grid noticeably longer (Coppa Italia 2026 middle: 168 minutes instead of the 142 actually used, where the real grid had 3 first-control collisions). With a different first control per category, as FISO asks, the same race fits in 128 minutes with wider intervals. If the window comes out too long, check first how many starters share the busiest first control (reported as a lower bound) and ask the course setter for more distinct first controls before shortening intervals.

## Questions To Ask The Organizer

- Which ranking to use for seeding (Coppa Italia, lista base, other) and for which categories.
- Elite blocks of 5 or 10.
- The maximum acceptable total window (otherwise it is computed from entries at about 5 starters per minute), the maximum interval (default 7 minutes) and whether sprint should also be widened.
- For weekends/multi-day events: the start lists of the previous races, so neighbours can be varied.
- Whether the window can grow if the master minimums make it too long, or whether extra start lanes are available.

## In Oribos

Oribos stores the interval per category (`<Intervallo>` on each `<categoria>`, see `read-file-og4`), so different intervals for masters and other categories can be carried over when the organizer enters the approved grid.
